# Request execution and security

- Cloud execution allows exact hostnames configured by the operator and exact hostnames explicitly approved by a platform administrator. Workspace users cannot execute an unreviewed host. Approval does not remove the executor's destination validation.
- Only HTTPS port 443 is accepted. URL user info, fragments, control characters, backslashes, literal/private IPs and hostname-suffix tricks are rejected.
- All A/AAAA answers are checked. Private, loopback, link-local, multicast, carrier-grade NAT, documentation, transition and other special ranges are rejected. cURL connects to a validated pinned address while verifying the original TLS hostname. Redirects and environment proxies are disabled.
- Transport headers cannot override Host, framing, connection or proxy controls. Sensitive saved headers require environment templates. Templates are expanded only on the server; undefined variables prevent execution.
- All environment values are encrypted at rest. Secret values are omitted from API responses and preserved only when a masked null is submitted. Changing a secret to public requires an explicit new value.
- Known secrets and sensitive response keys/headers are redacted before storing results. Stored execution URLs omit query values. Audit entries never include payloads. Redaction is a bounded defense: avoid pasting credentials directly into arbitrary URLs or raw body strings; use secret variables.
- Request bodies are limited to 64 KiB before expansion and 128 KiB afterward. Responses are capped at 256 KiB; oversized responses fail explicitly. cURL timeouts and quota/rate/concurrency limits bound execution. Runs are retained for 30 days by default.
- Assertions are declarative; no arbitrary JavaScript/PHP execution. OpenAPI import validates offline, resolves local references and rejects external references, custom dialects and YAML aliases.
- The private executor rejects missing/incorrect service tokens. In production it has no database credentials or application key. Its Docker network is separate from MySQL/Redis. Add a deployment firewall or egress gateway allowing only DNS and approved public HTTPS destinations; the included Compose network isolation alone is not a destination firewall.

The local machine uses loopback services and shares a host filesystem; this is a developer setup, not host-level process sandboxing. The optional Local companion has a separate one-session token and exact-origin check, binds only to loopback, rejects public HTTP, validates/pins public DNS, limits body/time/concurrency and does not browse local files. Loopback HTTP requires the developer to start it with an explicit authorization flag. Local responses reach browser JavaScript and are sanitized before reporting history, so this is a developer tool for trusted local sessions, not a server-side secret vault or protection against a compromised browser. See `LOCAL_EXECUTION.md` for all limits.

Public deployment requires HTTPS, private infrastructure, backed-up keys, verified egress controls and provider monitoring. The Docker topology is supplied for review but was not executed because this Windows host has no Docker installation.

Password recovery and verification tokens travel in URL fragments, are time-limited and omitted from server access URLs. Password resets revoke sessions and consume the reset token. Notifications are encrypted in the queue; local inbox files are encrypted at rest and available only to local admins. Production SMTP and provider delivery have not been connected. Workspaces opt into email/operator-webhook monitor alerts, with status records and retry deduplication. The operator webhook follows the same SSRF rules as requests.

Drafts are kept only in browser memory, cleared on logout, and protected by close/reload prompts. Browser persistent storage never receives request payloads, authentication tokens or secret values. Public registration cannot grant administration. `infrastructure/executor-firewall.sh` is supplied for Linux Docker hosts; its rules must be reapplied after executor recreation/reboot and verified on that host.
